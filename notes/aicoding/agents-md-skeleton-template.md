# AGENTS.md 骨架版模板（后端服务）

> 面向后端服务（Java/Go/Python，HTTP/RPC）的 AGENTS.md 起步模板。
> 遵循「第一步只写四样东西、故意不写 Conventions」的原则：够 AI 安全起步即可，编码规则等踩坑后再长出来。
>
> 用法：复制下面代码块，把 `<>` 占位符替换成你项目的真实内容，删除不适用的小节。

````markdown
## 目录

<!-- 模块地图，每个模块一行职责，不要展开细节。 -->

```
api/           对外 HTTP/gRPC 接口定义（proto / openapi）
internal/      领域服务实现（业务逻辑都在这里）
repo/          数据访问层，唯一允许接触数据库的地方
pkg/           跨模块共享的工具库
migrations/    数据库迁移脚本（禁止手改已有迁移）
config/        配置文件与配置加载
```

## 危险区

<!-- 改这些地方前必须先读什么 / 哪些地方绝对不能动。 -->

- 改 `api/` 下的契约（proto/openapi）前，先读 `docs/api-conventions.md`。
- `migrations/` 里已合入的迁移文件不可修改，只能新增。
- 改动数据模型前，先读 `docs/storage.md` 了解 schema 演进规则。

## 命令

<!-- AI 会用到的关键命令 + 行为预期，不是全部命令。 -->

```sh
make test           # 单元测试（不依赖外部服务）
make test-integration  # 集成测试（需要本地起 DB/docker compose）
make lint           # 静态检查 + 格式
make build          # 编译
make run            # 本地启动服务
```

## 验证

<!-- 什么改动配什么验证。 -->

- 改纯业务逻辑 → 补单元测试
- 改接口/契约 → 更新契约测试 + 集成测试
- 改数据模型 → 新增 migration + 数据层测试
- 提交前本地跑 `make lint && make test`
````

## 使用说明

### 1. 「系统」小节怎么写

**原则：一句话定义 + 一个核心不变式，不写愿景、不写背景故事。**

好坏对照：

| ❌ 不要写 | ✅ 要写 |
|---|---|
| "我们的使命是打造高效稳定的交易平台……" | "这是一个订单微服务，gRPC 对内，REST 对外" |
| "项目成立于 2020 年，经历了三次重构……" | "核心不变式：跨服务调用必须走 RPC 契约，禁止直连数据库" |

**「核心不变式」是最有价值的字段**——它是 AI 最容易违反、且违反后最难发现的规则，应该放在最显眼的位置。

### 2. 「目录」小节怎么写

**原则：地图，不是百科。** 每个模块一行职责，让 AI 能定位「我要改的东西在哪」。细节留给各模块自己的 README。

不要写满 20 个目录——只列 AI 大概率会碰到的核心模块。够定位即可。

### 3. 「危险区」小节怎么写

**原则：只写「改了会出事」的边界，不写通用规范。**

判断标准：这条如果 AI 不知道，会不会造成**线上事故或难以回滚的破坏**？
- 会 → 写进危险区
- 不会（只是代码写得不优雅）→ 不写，留给以后的 Conventions

### 4. 「命令」小节怎么写

**原则：命令 + 行为预期，不是命令罗列。**

每个命令的注释要回答「这条命令的副作用/前提」，尤其是 AI 会误判的：
- 哪些测试需要外部依赖（否则 AI 会以为测试挂了是代码问题）
- 哪些命令是门禁级（CI 会强制跑）

### 5. 「验证」小节怎么写

**原则：映射「改动类型 → 验证动作」，不要写「记得写测试」这种空话。**

好坏对照：

| ❌ 不要写 | ✅ 要写 |
|---|---|
| "修改代码请补充测试" | "改接口 → 更新契约测试 + 集成测试" |
| "保证代码质量" | "提交前本地跑 `make lint && make test`" |

## 这一版「故意不写」的东西（重要）

以下内容**第一步不要写**，等踩坑后逐步加：

| 不写 | 原因 | 何时补 |
|---|---|---|
| Conventions（编码规则） | 你现在不知道要约束 AI 什么，写错比不写更糟 | 用 AI 一周后，把反复犯的错固化成「可裁定」的规则 |
| 详细的「为什么」 | 会撑爆文件，稀释注意力 | 放 `docs/`，AGENTS.md 里只留「规则 + 链接」 |
| 反 AI 坏习惯的针对性条款 | 这些是「长出来的」，你踩了坑才知道要防什么 | 每踩一个坑加一条 |

## 终极自检

写完模板填空后，问自己：

> **如果我是第一次进入这个仓库的 AI，读完这份 AGENTS.md，我会不会「照着做错事」？**

- 会照着做错 → 删掉写错/写模糊的规则
- 读完不知道该怎么干活 → 缺了「系统本质 / 命令 / 验证」的关键信息
- 读完能安全起步、且不会犯「规则里有但没写清楚」的错 → 就是对的
